# lead-router — контур распределения лидов

**Демо:** https://lidgen.at-km.net — вход по логину, пароль у Марата.

Опрашивает гуглтаблицу лидгена, ведёт очередь назначений на команды, ставит пометки
обратно в таблицу и шлёт события в Аргус (СРМ).

```
Таблица (статус пустой) → карточка компании из Б24 → очередь → команда
   → компания в Аргусе на ответственного этой команды + «назначено» в таблицу
   → СРМ пишет в таблицу «в работе» / «отказ»
   → отказ = фрод: компания закрыта, команде записывается долг
```

Таблица здесь — двусторонний канал. Мы читаем новые строки и статусы, которые ставит СРМ,
и пишем «назначено». Кто наполняет таблицу — расширение Б24 или сама СРМ — контуру всё равно,
лишь бы держался формат колонок.

## Как работает очередь

Круг по умолчанию — `1,2,3,4,1,2,3,4…`, порядок задаётся полем `queue_order` команды.

**Две независимые очереди:** лиды и встречи ходят своими курсорами и не влияют друг на друга.
Вид берётся из колонки «тип лида» — какой именно, задано в `config/columns.json`.

**Отказ из СРМ = фрод от лидгена, и это долг перед командой.** Компанию, помеченную
отказом, СРМ снимает с команды в отстойник — дальше по кругу она не идёт и больше никому
не назначается. Но команда получила пустышку вместо своего хода, поэтому за ней остаётся
долг: следующую компанию она получит вне очереди.

```
назначили 1,2,3 → фрод у 1 → 1,4,1,2,3,4
```

Выдача в счёт долга круговой курсор не двигает — иначе команда, стоявшая следующей,
теряла бы свой ход из-за чужого фрода. Долги гасятся в порядке поступления и живут
в своей очереди: фрод по лиду не влияет на очередь встреч.

Когда долг погашен, в таблицу напротив **той самой фродовой строки** ставится галочка
в колонке `debt_closed` — видно, за какие отказы команда уже добрала, а за какие ещё нет.

Активных команд нет — компания уходит в «Эскалацию», на стол руководителю.

## Статусы

| В таблице | В контуре | Что происходит |
|---|---|---|
| пусто | `new` | ждёт распределения |
| `назначено` (ставим мы) | `assigned` | ждём реакции СРМ |
| `в работе` (ставит СРМ) | `in_work` | цикл закрыт |
| `отказ` (ставит СРМ) | `rejected` | фрод: компания закрыта + долг команде |
| — | `quarantine` | строка не прошла валидацию |
| — | `escalated` | отдавать некому |

## Запуск

```bash
npm install
cp .env.example .env                             # SHEETS_* и ARGUS_WEBHOOK_URL
cp config/columns.example.json config/columns.json  # раскладка колонок таблицы
npm run migrate
npm run seed              # опционально: 4 команды и демо-строки
npm start                 # http://localhost:3000
npm test
```

Опрос таблицы — раз в минуту (`IMPORT_INTERVAL_MS`). Без `SHEETS_SPREADSHEET_ID` контур
работает на строках, залитых через `POST /api/import/rows`, и пометки в таблицу не пишет.
Без `ARGUS_WEBHOOK_URL` вебхуки не копятся — всё остальное живёт.

## Схема таблицы

Колонки прибиты гвоздями к номерам — никакого поиска по заголовкам. Правится в
`config/columns.json` (пример — `config/columns.example.json`):

```json
{
  "sheet": "Лист1",
  "firstDataRow": 2,
  "columns": {
    "company": "B", "contact_name": "C", "phone": "D",
    "lead_gen": "E", "lead_type": "F", "status": "G"
  },
  "leadTypes": { "lead": "лид", "meeting": "встреча" },
  "statuses": { "assigned": "назначено", "in_work": "в работе", "declined": "отказ" }
}
```

Колонку можно писать буквой (`"D"`) или номером (`4`). Обязательные — `company`, `phone`,
`lead_type`, `status`; `contact_name`, `email`, `lead_gen`, `region` необязательны.
Значения типа и статуса сверяются с теми, что указаны здесь (регистр и лишние пробелы
не важны, синонимы не выдумываются). Кривой конфиг — дубль колонки или пропущенное
обязательное поле — роняет сервис на старте, а не молча портит данные.
Текущую схему видно в `GET /api/columns`.

## Импорт

- Ключ строки — `Лист:номер строки в таблице`, содержимое хешируется. Правку задним числом
  видно: данные обновляются, назначение не сбрасывается, в журнал ложится `source_row_changed`.
- Ячейки вне схемы не теряются: складываются в `raw` по буквам колонок.
- Телефон нормализуется (`901234567` → `+998901234567`).
- Строка без контактов или с типом, которого нет в конфиге, — в **карантин**, с указанием,
  что именно не сошлось. Дубль по телефону/почте/компании — туда же.
- Строка, у которой статус уже заполнен на момент первого импорта, в очередь не берётся.
  Помеченная фродом до нас — закрывается сразу, долг никому не пишется: своего хода команда
  на неё не тратила.

## Компания в Аргусе

Компания заводится **уже назначенной**: сначала очередь выбирает команду, и только потом
карточка уезжает в СРМ на ответственного этой команды. Поэтому порядок такой:

1. **До раздачи** — если в строке заполнена `b24_company_id`, тянем карточку из Б24
   (`crm.company.get` + `crm.contact.list` по `COMPANY_ID`, одним запросом на контакты —
   у крупных компаний их больше сотни) и складываем у себя. Без ИНН строка сразу
   в «Эскалацию»: Аргус компанию без ИНН не примет.
2. **Очередь** выбирает команду по обычным правилам.
3. **После назначения** — `companies.list` с `{"filter": {"INN": "..."}}`: компании нет —
   `companies.add` с `{"fields": {...}}`. Компания **уже есть** — карточку не трогаем совсем:
   она чья-то, отбирать её лидген не вправе. Такая строка закрывается как фрод, ход
   команде возвращается долгом, а руководителю команды того, кто ведёт компанию,
   уходит сигнал в телеграм — проверить, почему она попала в лидогенерацию.
   Ответственного берём из `ASSIGNED_BY_ID` в ответе Аргуса; пока Аргус это поле в
   `companies.list/get` не отдаёт, сигнал уходит в резервный чат `DUPLICATE_ALERT_CHAT_ID`.

Поля создания: `TITLE`, `INN` (обязательны), `ORGINFO`, `OKED` (свободный текст, как в Б24),
`PHONE[]`, `EMAIL[]`, `CONTACT_NAME/PHONE/EMAIL`, плюс два ключевых:

| Поле | Что кладём |
|---|---|
| `ASSIGNED_BY_ID` | `argus_user_id` команды, которой очередь отдала компанию |
| `LEAD_TYPE` | «Лид» или «Встреча» — из колонки типа |

Имена этих полей и значения типа правятся в `config/argus.json`, без правки кода.

**Получатель обязателен.** Если в команде никто не отмечен получателем, строка остаётся
назначенной, но в СРМ не уезжает, а в интерфейсе видно причину.

Доставка идёт с ретраями (5 попыток), назначение при этом не теряется — компания остаётся
за командой. Дубли не плодим: в журнале `argus_company_created` либо `argus_company_matched`.

Поля из Б24:

| Поле | Код в Б24 |
|---|---|
| Название | `TITLE` |
| ИНН | `UF_CRM_64DB2D1742285`, если пусто — `UF_CRM_UZB_INN_COMPANY` |
| ОргИнфо | `UF_CRM_1754989588` |
| ОКЭД | `UF_CRM_1754990395249` |
| Контакт | `NAME`, `LAST_NAME`, `SECOND_NAME`, `PHONE[]`, `EMAIL[]` |

Диспетчер Аргуса работает как у Б24: адрес несёт личность и права, тело оборачивается
в `fields`/`filter`, ошибки приходят конвертом `{"error": ..., "error_description": ...}`.
Потолок — 60 запросов в минуту на ключ; на 429 адаптер сам ждёт и повторяет один раз.

Пока компания не заведена, строка в очередь не идёт и в пуле не считается. Б24 или Аргус
не ответили — пять попыток с сохранением ошибки, после чего строка уходит в «Эскалацию».
Компания без ИНН в Аргус не поедет (он обязателен) — такая строка честно падает
в «Эскалацию» с текстом причины, а не молотит API впустую.
Строки с `b24_company_id` не требуют компании и телефона в самой таблице: всё придёт из Б24.

## Команда — это люди

У команды есть состав: несколько пользователей Аргуса. Один отмечен **получателем** —
на него заводится компания (`ASSIGNED_BY_ID`). Остальные числятся на уведомлениях;
отметить «в работе» или «отказ» может любой из них — контур смотрит на статус в таблице,
а не на то, чьими руками он поставлен.

Получатель в команде всегда один: отметил нового — с прежнего роль снимается автоматически,
и он остаётся на уведомлениях. Выключенный участник получателем не считается.

Правится в карточке команды: вкладка «Команды» → клик по названию. Там же вкладка
**«История изменений»** — кто когда добавлен, у кого забрали назначение, как менялся
порядок в очереди. Журнал пишется на каждую правку, задним числом ничего не пропадает.

| Метод | Путь |
|---|---|
| GET / POST | `/api/teams/:id/members` |
| PATCH / DELETE | `/api/teams/:id/members/:memberId` |
| GET | `/api/teams/:id/history` |

## Отметки времени

По каждой компании видно **когда назначена** и **когда последний раз менялся статус**,
плюс сколько она в нынешнем состоянии висит. Больше суток — подсвечивается красным,
чтобы залежавшееся не терялось в списке. Время показывается по местному часовому поясу.

## Вебхуки в Аргус

Транзакционный outbox: событие сначала в БД, воркер шлёт раз в 10 секунд с бэкоффом
`0 → 30с → 2м → 10м → 1ч`, дальше помечает `failed`. Аргус лёг — распределение продолжает работать.

События: `lead.assigned`, `lead.in_work`, `lead.declined`, `lead.escalated`.

```json
{
  "id": "uuid", "event": "lead.assigned", "occurred_at": "2026-09-07T10:00:00.000Z",
  "lead": { "id": 1, "source_key": "Лист1:2", "company": "ООО Ромашка",
            "phone": "+998901234567", "kind": "lead", "lead_gen": "Лидген-1",
            "status": "assigned", "raw": {} },
  "team": { "id": 1, "name": "Команда 1", "queue_order": 1 }
}
```

Тело подписывается HMAC-SHA256 (`ARGUS_WEBHOOK_SECRET`), заголовок `x-lead-router-signature`.

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/leads?status=&kind=` | компании с историей назначений |
| GET | `/api/teams` `/api/queues` | команды; состояние обеих очередей и превью |
| GET | `/api/stats` `/api/events` `/api/outbox` | счётчики, журнал, очередь вебхуков |
| POST | `/api/import` | опросить таблицу сейчас |
| POST | `/api/import/rows` | залить строки вручную `{rows: [{key, cells}]}` |
| GET | `/api/columns` | текущая схема таблицы |
| POST | `/api/dispatch` | разобрать пул |
| POST | `/api/enrich` | дозагрузить карточки компаний из Б24 |
| POST | `/api/deliver` | отправить назначенные компании в Аргус |
| POST | `/api/login` `/api/logout` | вход и выход |
| POST | `/api/leads/:id/assign` | по очереди или `{team_id}` вручную |
| POST | `/api/leads/:id/in-work` `/decline` `/release` `/escalate` `/kind` | правки вручную |
| POST/PATCH | `/api/teams` `/api/teams/:id` | команды, порядок, включение |

## Вход

Если заданы `AUTH_USER` и `AUTH_PASSWORD`, интерфейс закрыт формой входа: сессия живёт
12 часов в подписанной HttpOnly-куке (`SESSION_SECRET`). Пароль в репозитории не хранится —
только в `.env` на машине. Без этих переменных защита не включается, чтобы локально
не мешала. На http поставь `COOKIE_SECURE=0`, иначе кука не приедет.

## Интерфейс

`/` — Пул, Назначены, В работе, Фрод, Карантин, Эскалация, Очереди (цепочка кто следующий,
долги подсвечены), Команды (счётчики + вебхуки + пометки в таблицу).

## Развёртывание

Сейчас крутится на Mac Mini под launchd (`~/Library/LaunchAgents/net.at-km.lead-router.plist`),
порт 18902, снаружи — через cloudflared на `lidgen.at-km.net`. Логи:
`~/ai-server/logs/lead-router.log`. Перед переездом на рабочий сервер достаточно перенести
папку, `.env` и `config/columns.json` — база в `data/` едет вместе с историей.
